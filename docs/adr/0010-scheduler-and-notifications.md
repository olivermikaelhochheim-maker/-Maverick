# ADR 0010: In-process scheduler and Web Push

Status: Accepted (2026-10-24)

## Decision
- The scheduler runs **inside the Maverick server process** (Next.js `instrumentation.ts`), ticking every minute, instead of a separate worker. One process to start; nothing extra for Oliver to manage.
- Everything it does is idempotent: one briefing per kind per local day (unique key), reminders marked once sent. Restarts and overlapping ticks are safe.
- Times are Oliver's local time (Europe/Oslo, DST-aware). A missed run (Mac asleep) catches up within a window: morning 6h, evening 2h, weekly 6h.
- Briefings use the standard model (Sonnet 5.5) when the budget allows, and otherwise a **free template** built from real calendar/task/goal data. They never silently fail on budget.
- Notifications use standard **Web Push** (VAPID keys generated by `pnpm configure`; payloads are end-to-end encrypted by the protocol). Policy: explicit consent in Settings, per-device opt-in, quiet hours (reminders are held until they end), daily cap (default 6). Push endpoints are restricted to the real push services, so a crafted subscription can't make Maverick call arbitrary URLs.

## Consequences
- The Mac must be running Maverick and awake (README: `caffeinate -is`, `pmset` wake) for on-time briefings. Moving to an always-on cloud host (ADR 0007) removes this.
- iOS delivers web push only to home-screen web apps over HTTPS, hence the Tailscale `serve` setup.
